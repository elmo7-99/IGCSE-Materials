# نتيجة مراجعة مشاريع GitHub — 8 أكتوبر 2026

## القرار

أفضل أساس مفتوح المصدر لإدارة محادثات العملاء: **Chatwoot Community**. أسرع مسار عملي لدورة طلبات الكتب الحالية: **نواة الطلبات المرفقة + n8n + WhatsApp Cloud API**؛ ثم ربط Chatwoot عندما تحتاج صندوق محادثات للفريق. هذا ترجيح هندسي بناءً على ملاءمة المتطلبات، وليس نتيجة اختبار أداء مقارن.

لم أجد ضمن المشاريع السبعة المفحوصة مشروعًا جاهزًا يحقق جميع مراحل مشروعك كما هي: التسجيل الاستباقي من الفورم، صورة أسعار مدرس محدد، الاختيار والكمية، رسوم مدينة معتمدة، الموقع، مراجعة تحويل بنكي، وتجهيز ثم شحن وتسليم. لذلك بُنيت طبقة الطلبات نفسها مستقلة، مع استخدام n8n للأتمتة؛ لا حاجة إلى تعديل آلاف ملفات منصة خدمة عملاء لتغيير ثلاثة تدفقات.

## أدلة المراجعة وحدودها

- راجعت صفحات المستودعات الأساسية وملفات تراخيص Chatwoot وn8n وActivepieces وEvolution وWAHA.
- قرأت JSON الفعلي لمشروع dotabdullah: recipientPhoneNumber قيمة ثابتة، والمخزون والطلبات أدوات Google Sheets تحت AI Agent. المشكلة ملموسة في الملف وليست حكمًا على اسم المشروع.
- في مشروع sujal0018 فرّقت بين ما يصفه README وما يظهر فعلًا في ملفات الجذر. لم أعتبر وصفًا تسويقيًا دليلاً على تنفيذ.
- قرأت مستند n8n الرسمي لدعم إرسال الرسائل والقوالب والوسائط، ومستند ترخيصه الذي يجيز الاستخدام الداخلي ضمن حدوده.
- GitHub API أفاد وقت المراجعة بأن ترخيص dotabdullah غير محدد. وجود كود عام لا يمنح تلقائيًا ترخيصًا لإعادة استخدامه.
- لم أثبّت المشاريع السبعة، ولم أجر تدقيقًا أمنيًا شاملًا أو اختبار حمل عليها. لا توجد ضمانات استقرار أو مدد نشر مقاسة من هذه المراجعة.
- الحزمة الحالية ليست fork لأي مشروع من هذه المشاريع. هي نواة أصلية قابلة للتشغيل مع n8n؛ ويظل Chatwoot توصية لتوسعة إدارة المحادثات.

## ما نحتفظ به وما نؤجله

نحتفظ بمصدر أسعار معتمد، رقم طلب ثابت، معالجة ردود محددة، أرشفة الإيصال، اعتماد الدفع، سجل الأحداث، أتمتة رسائل، والتدخل اليدوي عند الغموض.

نؤجل البحث المتجهي/Pinecone، وكيلًا عامًا يقرر الحالات المالية، متجرًا كاملًا، قنوات دعم غير WhatsApp، وقاعدة CRM ضخمة؛ لا تضيف هذه العناصر قيمة لازمة لدورة الطلب الأولى. يمكن إضافة AI لاحقًا لفهم الأسئلة أو استخراج حقول إيصال، مع إبقاء تأكيد وصول الأموال خارج قرار النموذج.

## ما يلزم للإطلاق الحي

1. رقم WhatsApp Business Platform متصل ومفاتيحه؛ التطبيق العادي وحده لا يفعّل موصل Cloud API.
2. صور الأسعار الخاصة بكل مدرس، والقوالب المعتمدة وأكواد لغاتها.
3. رسوم المدن والاسم الكامل لصاحب الحساب وIBAN.
4. أسماء حقول الفورم الدقيقة وإضافة موافقة على تحديثات الطلب.
5. خادم HTTPS دائم، ثم تجربة طلب حي واحد من تسجيل إلى استلام رسالة الشحن، ومراجعة Logs.
6. اعتماد التحويل من الحساب البنكي أو ربط بوابة دفع موثوقة؛ تحديث حالة الشحنة من الإدارة أو شركة توصيل.

الكود مفتوح المصدر لا يعني أن خدمة Meta أو الاستضافة أو شركة التوصيل مجانية. لم أضع تكلفة تقديرية غير موثقة.
