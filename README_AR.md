# IGCSE — أتمتة طلبات الكتب

حزمة أولية قابلة للتشغيل محليًا، مبنية كنواة طلبات مستقلة يمكن تشغيلها مع n8n. لم يتم تشغيل إرسال واتساب فعلي أو نشرها على خادم خارجي. الكود المخصص مكتوب لهذه المهمة، وليس نسخة من Chatwoot أو مشاريع الطعام.

## ما يعمل الآن

- إدارة الطلبات عبر لوحة عربية؛ إضافة سطر من الشيت أو CSV أو Google Forms بواسطة السكربت المرفق.
- 16 باقة وأسعار البيع مستخرجة من أحدث ملف Word المتاح J27_Packages_Final_Formatted.docx، الذي يحمل جدول 7 أكتوبر 2026. لا تشمل الأسعار التوصيل. لا تُعرض تكلفة الطباعة أو الربح للعميل.
- إرسال صورة أسعار المدرّس ضمن قالب البداية عند توفير رابط الصورة والقالب المعتمد.
- رحلة محددة: اختيار الباقة والكمية، موقع واتساب، عنوان مكتوب، بيانات التحويل، استلام صورة أو PDF، مراجعة الدفع، التجهيز، الشحن، التسليم.
- رسائل عربية وإنجليزية، وحساب المبالغ بالفلس لتجنّب أخطاء الكسور.
- منع تكرار التسجيل وإعادة معالجة نفس رسالة واتساب، ودعم أكثر من طلب لنفس ولي الأمر مع اختيار الطلب صراحة قبل متابعة الردود، حتى لا تختلط المواد أو الإيصالات.
- إيقاف عند STOP / إيقاف، وتسليم لموظف عند STAFF / موظف أو بعد ثلاثة ردود غير مفهومة.
- حفظ الإيصال محليًا من Meta عند الربط الفعلي؛ مراجعة يدوية لمطابقة وصول المبلغ إلى البنك، ومنع تكرار مرجع التحويل.
- سجل أحداث، قائمة رسائل، توقيع HMAC لخطاف Meta، مفاتيح منفصلة للإدارة والتسجيل.
- تذكير واحد بعد 24 ساعة لطلب غير مكتمل. الطلبات والرسائل تبقى محفوظة في SQLite.
- موصل إرسال Meta فعلي في الكود، مع قوالب خارج نافذة المحادثة؛ غير مختبر بحساب حي.

## تشغيل محلي سريع

يتطلب Python 3.11 أو أحدث، دون تثبيت مكتبات لتشغيل الخدمة.

```bash
cp .env.example .env
python3 -c 'import secrets; print(secrets.token_urlsafe(32)); print(secrets.token_urlsafe(32))'
```

ضع مفتاحين مختلفين في ADMIN_API_KEY وINTAKE_API_KEY داخل .env، واترك SEND_LIVE=false.

```bash
python3 server.py
```

افتح http://127.0.0.1:8080 ثم أدخل مفتاح الإدارة. عدّل الكتالوج والبنك ورسوم التوصيل من «إعداد الأسعار والبنك». تُحفظ النسخة الجارية في data/config.json؛ ملف config.json هو نسخة البداية فقط. عندما يبدأ الخادم لا تنعكس تعديلات نسخة البداية على نسخة البيانات تلقائيًا.

## إعداد مطلوب قبل استقبال طلبات فعلية

1. ضع صورة أسعار HTTPS مستقلة لكل مدرس في image_url لكل باقاته. يجب أن يكون الرابط قابلًا للوصول لدى Meta. تأكد أن الصورة تطابق قائمة الأسعار.
2. أضف رسوم كل مدينة بالنص المطابق للفورم، مثل "Sharjah (الشارقة)": المبلغ بالفلس. لم نفترض أي رسوم.
3. أكمل اسم صاحب الحساب والـIBAN الصحيحين. لم تُستكمل بيانات ناقصة من الذاكرة.
4. تأكد من توافر الكتب قبل إبقاء الباقة active=true. الأسعار مأخوذة من الملف، والتوافر لم يُتحقق منه.
5. الباقة OL في الرياضيات واحدة فقط في المصدر الحالي؛ أضف الباقات الجديدة من ملف اعتمادها، دون تخمين الأسعار.
6. أضف خيار موافقة واضح إلى الفورم: «أوافق على تلقي تحديثات طلبي عبر واتساب». لا تستورد سجلات قديمة على أنها موافقة تلقائيًا.
7. عيّن Language صراحة إلى Arabic أو English. لا تُستنتج لغة العميل من اسمه.

## ربط Google Forms

انسخ integrations/google-forms.gs إلى Apps Script المرتبط بشيت الردود. خزّن ORDERS_BASE_URL وINTAKE_API_KEY في Script Properties.

السكربت الآن مخصص للشيت الفعلي ويتعامل مع تكرار عمود ?level. بعد إعداد عنوان HTTPS ومفتاح التسجيل، شغّل setupRegistrationAutomation مرة واحدة؛ ينشئ المشغلين ويضيف سؤال موافقة تحديثات واتساب إلى الفورم المرتبط. راجع دليل VERSION_2_AR.md قبل تشغيله. ينشئ السكربت ورقة AutomationQueue؛ الطلبات الفاشلة تعاد حتى 10 محاولات، وأخطاء البيانات تُحوّل إلى REVIEW. إعادة إرسال نفس الصف لن تنشئ طلبًا جديدًا. لا يعمل السكربت مع ملف Excel محلي دون تصديره أو استيراده.

لـCSV استخدم أعمدة integrations/intake_template.csv، ثم شغّل import_csv.py. القيمة consent مطلوبة صراحة. يمكن حفظ Excel بصيغة CSV UTF-8؛ لا تستخدم معرف مصدر متغيرًا عند إعادة استيراد نفس السجل.

## ربط واتساب الرسمي

وفر الرقم في Meta WhatsApp Business Platform، واختر META_GRAPH_VERSION مدعومًا من إعداداتك الحالية. أضف META_ACCESS_TOKEN وMETA_PHONE_NUMBER_ID وMETA_APP_SECRET وMETA_VERIFY_TOKEN. ضع خلف الخدمة عنوان HTTPS دائمًا، ثم سجل https://YOUR_DOMAIN/webhooks/meta وفعّل أحداث messages.

أنشئ قوالب مناسبة واعتمدها من Meta وفق docs/WHATSAPP_TEMPLATES.md، ثم أدخل أسماءها وأكواد اللغات الفعلية في الإعدادات. التسجيل في الفورم لا يفتح نافذة محادثة واتساب. رسالة البداية دائمًا قالب معتمد بصورة؛ المتابعات خارج نافذة 24 ساعة تستخدم قالبًا معتمدًا.

استعرض الرسائل المعلقة قبل SEND_LIVE=true. بعد التغيير أعد تشغيل الخادم. لا يكفي التطبيق العادي وحده لتفعيل الموصل الرسمي، وأهلية استخدام الرقم نفسه مع التطبيق تحتاج تحققًا عند ربط الحساب.

## n8n

استورد integrations/n8n-operations.json. عيّن لكل HTTP node بيانات اعتماد Header Auth باسم Authorization وقيمة Bearer ADMIN_API_KEY. العنوان داخل Docker هو http://orders:8080؛ إذا استُخدم n8n في مكان آخر غيّره إلى عنوان الخدمة الذي يستطيع الوصول إليه.

مسار التشغيل كل خمس دقائق يضيف التذكير المحدود ثم يطلب معالجة الرسائل. العامل داخل الخدمة يعالج الرسائل كل خمس ثوانٍ؛ طلب n8n لا يكررها، لأن السحب من القائمة ذري.

n8n-intake.json بديل لاستقبال تسجيل موحّد: عيّن Header Auth للـWebhook لحماية نقطة الدخول، وHeader Auth منفصلًا لنداء /api/intake باستخدام INTAKE_API_KEY. لا تفعّل المسار قبل إضافة بيانات الاعتماد. سكربت Google Forms يتصل بالنواة مباشرة؛ لا يحتاج هذا المسار الإضافي.

compose.yaml يشغّل الخدمة وn8n محليًا. ضع N8N_IMAGE بإصدار/بصمة راجعتها، وN8N_ENCRYPTION_KEY قويًا، وقيمة N8N_WEBHOOK_URL صحيحة عند النشر. Docker غير متاح في بيئة التنفيذ الحالية، لذا لم نختبر Compose أو استيراد n8n تشغيليًا.

## الدفع والتوصيل

استلام صورة إيصال يغيّر الحالة إلى PAYMENT_REVIEW فقط. بعد التأكد من وصول المبلغ الصحيح للحساب تضغط «اعتماد الدفع» وتضيف مرجع البنك، فيبدأ التجهيز وتخرج رسالة التأكيد.

الشحن يحتاج تاريخًا ومرجع شحنة من الإدارة أو تكامل شركة التوصيل. يتم إغلاق الطلب بعد إدخال دليل التسليم. لا يوجد ربط بنك، بوابة دفع، شركة شحن أو OCR حي في هذه النسخة؛ يمكن إضافتها عبر /api/actions بعد التحقق من مصدر الحدث. لا تعني علامة تسليم رسالة واتساب أن الكتب وصلت.

أي طلب في REVIEW يحتاج إصلاح الإعداد الناقص ثم «إعادة مراجعة الباقات»؛ هذا يعيد تأكيد الباقة والكمية والعنوان من البداية. الأسئلة الحرة تسجل للمراجعة؛ لا يوجد نموذج ذكاء اصطناعي يقرر الأسعار أو يؤكد المال.

## التشغيل الخارجي

هذه خدمة Python خفيفة وليست خادمًا إنتاجيًا معتمدًا بذاتها. للنشر استخدم HTTPS reverse proxy، مفاتيح قوية، نسخًا احتياطية مشفرة لـdata، مراقبة قائمة failed/blocked/uncertain، وقيود الوصول إلى الإدارة. لا تنشر SQLite أو مجلد الإيصالات كملفات عامة. تنتهي صلاحية تنزيل Meta للإيصالات، لذلك تحقق من أرشفتها فور وصولها.

إذا توقف عامل الإرسال أثناء إرسال رسالة، تصنّف uncertain. راجع وصولها لدى المزوّد قبل استخدام «إعادة رسالة متعثرة». هذا يمنع التكرار الأعمى. الرسائل المعلقة أو الفاشلة الأقدم تمنع الرسائل التالية لنفس الطلب حتى تُراجع.

Chatwoot هو الأساس المقترح لإدارة المحادثات عند توسيع الفريق؛ ليس منصّبًا ولا موصولًا في هذه النسخة. تجنّب جعل Chatwoot والنواة مالكين مستقلين لنفس أحداث WhatsApp قبل تنفيذ جسر واحد، حتى لا تتكرر الرسائل أو يتعارض callback. لوحة النواة تغطي إدارة الطلبات الحالية.
